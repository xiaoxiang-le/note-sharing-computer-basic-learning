
面向对象设计的五大原则通常指 **SOLID** 原则，具体如下：

## 1. 单一职责原则（SRP）

> 一个类只应有一个引起它变化的原因。

**反例**：  
一个 `Report` 类既负责从数据库取数据，又负责生成 HTML 报表。数据源变化或报表格式变化都会导致这个类被修改。

```java
class Report {
    void fetchData() { ... }   // 访问数据库
    void formatToHtml() { ... } // 生成 HTML
}
```

**正例**：  
拆分为两个类，各司其职。


```java
class DataFetcher {
    void fetchData() { ... }
}
class HtmlFormatter {
    void format(Data data) { ... }
}
```

---

## 2. 开放-封闭原则（OCP）

> 对扩展开放，对修改封闭。即增加新功能时不修改已有代码。

**反例**：  
计算不同形状的面积，用 `if-else` 判断类型，每增加一种形状就修改这个函数。

```java
double area(Object shape) {
    if (shape instanceof Circle) { ... }
    else if (shape instanceof Rectangle) { ... }
    // 加三角形时，必须修改此处
}
```

**正例**：  
使用抽象/接口，新形状只需新增类。

```java
interface Shape {
    double area();
}
class Circle implements Shape {
    public double area() { return r * r * 3.14; }
}
class Rectangle implements Shape {
    public double area() { return w * h; }
}
// 新增 Triangle 同样实现 Shape，不必修改 area 调用方
```

## 3. 里氏替换原则（LSP）

> 子类必须能够替换掉父类，且程序行为正确。

**反例**：  
`Bird` 类有 `fly()` 方法，`Penguin` 继承自 `Bird` 但不会飞，覆盖 `fly()` 为空或抛异常。此时用 `Bird` 引用来调用 `fly()` 会出错。

```java
class Bird {
    void fly() { ... }
}
class Penguin extends Bird {
    void fly() { throw new Exception("我不能飞"); }
}
```

**正例**：  
设计更合理的类层次，例如区分 `FlyingBird` 与 `NonFlyingBird`。

```java
abstract class Bird { ... }
interface Flyable { void fly(); }
class Sparrow Bird implements Flyable { ... }
class Penguin extends Bird { ... }  // 不实现 fly
```

## 4. 接口隔离原则（ISP）

> 不应强迫客户端依赖它们不使用的接口。大接口应拆分为多个小接口。

**反例**：  
一个 `Worker` 接口包含 `work()`、`eat()`、`sleep()`。机器人实现时必须空实现 `eat()` 和 `sleep()`。

```java
interface Worker {
    void work();
    void eat();
    void sleep();
}
class Robot implements Worker {
    public void work() { ... }
    public void eat() {}   // 没用
    public void sleep() {} // 没用
}
```

**正例**：  
拆分为 `Workable`、`Eatable`、`Sleepable`，机器人只实现 `Workable`。

```java
interface Workable { void work(); }
interface Eatable { void eat(); }
interface Sleepable { void sleep(); }
class Human implements Workable, Eatable, Sleepable { ... }
class Robot implements Workable { ... }
```

## 5. 依赖倒置原则（DIP）

> 高层模块不应依赖低层模块，二者都应依赖抽象；抽象不应依赖细节，细节应依赖抽象。

**反例**：  
`LightSwitch` 直接依赖 `LightBulb`，换用 `Fan` 时需修改 `LightSwitch`。

```java
class LightBulb {
    void turnOn() { ... }
}
class LightSwitch {
    private LightBulb bulb;
    void operate() { bulb.turnOn(); }
}
```

**正例**：  
引入 `Switchable` 接口，高层 `Switch` 依赖抽象。

```java
interface Switchable {
    void on();
    void off();
}
class LightBulb implements Switchable { ... }
class Fan implements Switchable { ... }
class Switch {
    private Switchable device;
    void flip() { device.on(); }
}
```
## 6.无环依赖原则（ADP）

**核心思想**：模块（或包、组件）之间的依赖关系不能形成循环（即依赖图必须是一个**有向无环图**，DAG）。如果 A 依赖 B，B 依赖 C，那么 C 不能直接或间接依赖 A。
## 多态类型
- **参数多态**（Parametric）：通过类型参数实现，同一个函数或类型可以对不同的数据类型进行统一操作，例如C++模板、Java泛型。
    
- **包含多态**（Inclusion）：即子类型多态，通过继承和虚函数实现，派生类的对象可以被当作基类对象使用，运行时根据实际类型决定行为。
    
- **强制多态**（Coercion）：通过隐式或显式类型转换，将一个类型视为另一种类型，例如 int 转 double。
    
- **过载多态**（Overloading）：同一作用域内多个同名函数具有不同的参数列表（类型或个数），编译器根据上下文（调用时提供的参数）决定调用哪个函数
