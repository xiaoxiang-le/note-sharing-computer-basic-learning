**前驱图**，又称**优先图**或**依赖图**，是用于描述一组任务（或进程、语句、事务）之间**执行顺序约束**的有向无环图。它直观地刻画了“某个任务必须在另一个任务开始之前完成”的偏序关系，是并发控制、任务调度、数据流分析等领域的基础工具。
## 1. 形式化定义

前驱图可以表示为一个二元组 G=(V,E)G=(V,E)：

- **节点集合 V**：每个节点代表一个任务、进程、指令或事务（记为 P1,P2,…,PnP1​,P2​,…,Pn​）。
    
- **有向边集合 E**：若存在一条从节点 Pi​ 指向 Pj 的边 (Pi→Pj)(Pi​→Pj​)，则表示 Pi​ 是 Pj 的**直接前驱**，Pj​ 是 Pi​ 的**直接后继**。语义为：Pj 必须在 Pi​ **完成之后**才能开始执行。

因此，边蕴含了**偏序关系**：Pi≺Pj​（Pi​ 先于 Pj​）。
## 2. P 和 V 操作

- **P 操作（荷兰语 _Proberen_，意为“测试”）**：通常对应 `wait(S)` 或 `down(S)`，表示**申请资源**或**等待条件**。执行时会将信号量 S 的值减 1，若结果 < 0 则阻塞调用进程。
    
- **V 操作（荷兰语 _Verhogen_，意为“增加”）**：通常对应 `signal(S)` 或 `up(S)`，表示**释放资源**或**发出信号**。执行时会将信号量 S 的值加 1，若有进程阻塞在 S 上则唤醒其中一个。
- 
假设任务 Pj 有 k 个直接前驱（入度为 k），那么：

- 定义一个信号量 Sj，初始值为 00。
    
- 每个前驱任务 PiPi​ 在执行完自己的代码后，执行 **V(Sj​)**，表示“我已完成，向你发出一个信号”。
    
- 任务 PjPj​ 在执行自己的代码**之前**，需要依次（或循环）执行 kk 次 **P(Sj)**，以确保所有前驱都已经完成了 V 操作。
    

如果 k>1，则 PjPj​ 需要等待 k 次 V 操作才能通过 k 次 P 操作（因为每次 P 会将信号量减 1，初始为 0 时，P 会阻塞，直到有 V 将其加回正数）。
```c
P1() {
    // P1 的工作
    V(S2);   // 通知 P2：我已完成
    V(S3);   // 通知 P3：我已完成
}

P2() {
    P(S2);   // 等待 P1 完成
    // P2 的工作
    V(S4a);  // 通知 P4：我（P2）已完成
}

P3() {
    P(S3);   // 等待 P1 完成
    // P3 的工作
    V(S4b);  // 通知 P4：我（P3）已完成
}

P4() {
    P(S4a);  // 等待 P2 完成
    P(S4b);  // 等待 P3 完成
    // P4 的工作
}
```
